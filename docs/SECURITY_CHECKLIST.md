# Daftar Periksa Keamanan Sistem SIRKULA (OWASP Top 10)

Dokumen ini memetakan implementasi arsitektur SIRKULA terhadap risiko keamanan standar OWASP Top 10.

| Kategori Risiko OWASP | Penerapan & Mitigasi pada SIRKULA | Status |
|---|---|---|
| **A01: Broken Access Control** | - **Row-Level Security (RLS)** aktif di seluruh tabel PostgreSQL.<br>- Pemisahan wewenang multi-tenant berbasis peran (`user_role`) dan fasilitas (`facility_id`).<br>- RPC `public.apply_op` memvalidasi peran per jenis operasi (`op_type`) di sisi server.<br>- Pengelola fasilitas A tidak dapat memanipulasi data fasilitas B. | ✅ Terverifikasi |
| **A02: Cryptographic Failures** | - Seluruh audit trail dirantai menggunakan algoritma standar industri **SHA-256**.<br>- Token konfirmasi penerima disimpan hanya dalam bentuk hash bergaram (`token_hash = SHA-256(token + TOKEN_PEPPER)`). Token mentah tidak disimpan di basis data.<br>- Enkripsi data bergerak (*in-transit*) menggunakan HTTPS/TLS 1.3 dan HSTS. | ✅ Terverifikasi |
| **A03: Injection** | - Seluruh query menggunakan parameter terikat (*parameterized queries* / PL/pgSQL).<br>- Tidak ada perakitan query SQL dinamis yang tidak terikat string.<br>- Validasi skema input menggunakan tipe data ketat dan RPC PostgreSQL terstruktur. | ✅ Terverifikasi |
| **A04: Insecure Design** | - **Protokol Konfirmasi Buta (*Blind Confirmation*):** Desain sistem mencegah kebocoran angka bobot pengirim ke mitra penerima untuk menjamin keaslian bukti audit.<br>- Rantai audit bersifat *Append-Only* dengan trigger `app.block_mutation()` dan `app.block_delete()`. Tidak ada opsi hapus keras. | ✅ Terverifikasi |
| **A05: Security Misconfiguration** | - Pendaftaran publik (*public sign-up*) dimatikan di Supabase Auth; akun dibuat secara terkelola oleh administrator.<br>- Header keamanan HTTP (`X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy`) dikonfigurasi pada `_headers` dan `vercel.json`.<br>- Kunci rahasia layanan (*Service Role Key*) hanya tersimpan di Edge Functions dan tidak pernah terekspos ke bundel klien. | ✅ Terverifikasi |
| **A06: Vulnerable and Outdated Components** | - Dependensi diperbarui dan dipindai secara berkala.<br>- Tidak ada paket backend eksternal yang tidak terpakai.<br>- Kompilasi TypeScript ketat dengan `strict: true`. | ✅ Terverifikasi |
| **A07: Identification & Authentication Failures** | - Otentikasi berbasis Supabase Auth dengan JWT dan sesi aman.<br>- Token konfirmasi mitra kedaluwarsa otomatis (72 jam) dan dibatalkan seketika setelah digunakan satu kali. | ✅ Terverifikasi |
| **A08: Software and Data Integrity Failures** | - Fungsi integritas `public.verify_chain()` memverifikasi setiap tautan hash $H_n = \text{SHA-256}(H_{n-1} \| \text{payload})$ di tingkat basis data.<br>- Setiap manipulasi baris langsung pada database langsung memutus verifikasi rantai secara terdeteksi. | ✅ Terverifikasi |
| **A09: Security Logging & Monitoring** | - Setiap transaksi mutasi (`INSERT`, `UPDATE`, `VOID`) memicu pencatatan audit otomatis via trigger `app.log_event()`.<br>- Penjangkaran hash mingguan ke tabel `hash_anchors` menyediakan rekam jejak berkala yang dapat diaudit regulator/dinas. | ✅ Terverifikasi |
| **A10: Server-Side Request Forgery (SSRF)** | - Edge Functions tidak melakukan panggilan keluar (*outbound request*) ke URL sembarang yang ditentukan oleh klien.<br>- Pembatasan CORS hanya untuk origin terpercaya. | ✅ Terverifikasi |
